# Py仓 文档入代码仓

## 确认来源和目标

1. 读取当前文档，沿用其最新身份和版本。来源在 Library 时先解析该文件；本地已有相同版本时直接使用，不覆盖已完成的编辑。使用 Library 当前指引处理必要的下载。
2. 根据当前指令与已确认的上下文解析目标仓库。用户吴孟城此前的默认仓库为 `wu709621493/motionbricks`，PyIgnite 目前也在该仓库内；每次核对远端元数据。明确指定其他仓库时使用指定仓库；有互相冲突的目标证据时再询问。
3. 读取目标分支、当前提交、相关目录、适用的 `AGENTS.md` 和贡献规范。优先使用 GitHub 连接器。记录读取到的基准 SHA，保留其他人的更改。
4. 把“将这份文档入仓”视为对这份已指定文档的提交与创建 PR 的授权。默认保留 PR 开放，不自动合并。已有授权时不要重复确认；不要将授权扩展到其他文件、通知收件人或未来任务。

## 整理文档

- 保留原件字节、版本号、作者原话和来源链接。未经要求不要顺手重写观点、改动措辞或替换引文。
- 将事实、作者评价、文学引文和未验证判断的既有区分保留下来。归档过程不重新证明文章结论；新增事实时另行查证。
- 将可审阅正文写为 Markdown，并将原件放在同一归档目录。按仓库惯例增加入口链接，避免无关代码或依赖变动。
- 对仅包含段落与超链接的简单 DOCX，使用本技能脚本；脚本拒绝不能可靠转换的结构，避免静默遗漏。

```bash
python -S /absolute/skill/path/scripts/prepare_document.py \
  /absolute/source.docx --output-dir /absolute/new/archive-directory \
  --stem policy_accountability_v0.2 --version 0.2
python -S /absolute/skill/path/scripts/prepare_document.py \
  --verify /absolute/new/archive-directory
```

脚本生成 Word 原件、Markdown 正文和 `manifest.json`。输出目录必须不存在；版本需与 DOCX 属性一致（若该属性存在）。脚本仅准备归档，绝不联网、改写来源、提交或合并。需要处理表格、图片、脚注、批注、修订、自动列表或其他格式时，使用相应文档工具完成可核查的转换，保留原件并检查是否遗漏。

## 提交与回读

1. 完成有针对性的检查：原件散列一致，Markdown 文字及引文完整，引用与仓内链接有效，清单可验证。只报告实际执行的检查；不要将本地验证称为 CI 成功。
2. 创建独立分支。文本可以使用 GitHub tree 内容或 UTF-8 blob；二进制原件必须使用 base64 blob。继承读取到的完整基准 tree，只加入本次文件，再创建 commit 和分支；不得新建一个只含新增文件的根 tree 覆盖仓库。
3. 创建 PR，写清文档主题、版本、技能作用和实际验证结果。保留当前授权范围，遵循既有的 PR 状态约束。
4. 回读 PR 状态、head SHA 和文件清单。核对远端正文与本地文字；二进制可用 Git blob SHA 与本地 `sha1("blob " + 字节数 + NUL + 原件字节)` 比较，证明远端是原件。
5. 遇到目标分支变化或租约冲突时先重新读取，保存他人更改，不强推。没有拿到远端提交或 PR 回执时，明确报告未完成的步骤。

## 交付

简短报告 PR 链接、文档入口、技能是否已安装，以及 PR 是否合并。区分仓内技能文件与个人技能安装；只有完成个人技能保存及远端核验后才称为已安装。不要向用户提供临时令牌、内部文件身份或未经核实的成功状态。
