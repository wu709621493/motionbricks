# 如果由我负责苹果：中文输入互操作条款提案

2026-11-08 · 角色视角写作与产品建议，非 Apple 官方声明

## 产品决定（拟）

我会批准一个小范围实验：把拼音提示放到注音键帽上，让已经会拼音的人，能够靠现有知识开始使用注音。技术团队提供可核验的音节转换；用户研究团队实测首次输入时间与错误率；协议团队把数据承诺写成用户读得懂、工程做得到的条款。

北京、华盛顿、台北以及其他地方的中文使用者，可以选择自己熟悉的字形和读音提示。能否真正降低门槛，由试用结果回答。我们不把某种输入习惯解释成用户的身份或立场，也不把愿景写成已经得到全球用户赞同的事实。

## 建议新增的「中文输入与学习辅助」条款

以下为新拟文字，不是假称逐字修改了某一版现行 Apple 用户协议。只有相应协议主体履行自己的审议与发布流程，条款才可能生效。

1. **输入习惯由用户决定。** 用户可以自主选择拼音、注音、辅助标注、繁体或简体。提供者应说明实际支持的语言与地区读音范围，不以输入习惯推断或要求用户声明国籍、政治身份或文化归属。
2. **基础功能保持本地可用。** 双标键帽、基本组字和内置候选不以开放完整网络权限、建立账号或参与数据收集为条件。用户可随时切换或移除键盘。
3. **输入内容不成为附带授权。** 使用输入法不表示同意开发者复制、训练、广告利用或跨应用分析输入内容。未来可选联网功能须逐项说明和单独选择；不得由泛化的“改善服务”句子覆盖新的用途。
4. **辅助提示应可解释。** 提示须区分声母/韵母与整音节拼写；对词库缺失、地区读音差异和未支持特性作清晰说明。不得用未经验证的映射误导用户，或静默用错误文字替换未识别组合。
5. **变更应保留选择。** 涉及收费或数据用途的实质变化应先告知；拒绝可选用途不应剥夺已经提供的基本离线输入。用户可以撤回选择、退出和移除输入法。
6. **输入辅助不构成内容立场。** 字形、地名、候选和词例用于完成用户输入，不被提供者用来为用户推定政治观点。候选排序规则与地区读音设置应有可查说明。
7. **学习负担也应纳入产品质量。** 评价输入工具时，除速度与价格外，应测量新用户完成任务的时间、纠错次数、提示开关后的迁移能力和无障碍可用性，不通过评分或广告解锁基本功能。

## 工程承诺与代码的对应

| 承诺 | pre-PR 中的实现 / 尚缺内容 |
|---|---|
| 注音加拼音 | 37 键双标、409 音节拼写；关提示开关 |
| 离线基础输入 | 204 条教学词库；`RequestsOpenAccess=false`；无网络 SDK |
| 不保存输入历史 | 仅内存组合；未使用 UserDefaults、文件写入或上下文读取 |
| 可切换 | 系统地球键交互与简繁开关；需真机验证 |
| 可解释的拼写 | `zhi/ju/you/liu/lü` 等明确例子与异常测试 |
| 用户效果证据 | 尚无用户试验；不能声称“普遍零学习成本” |

这些是本原型的设计和本次提案，不等于 Apple 现行规则原本没有保护隐私。苹果现行键盘审核要求已经包括无需完全访问仍可工作、能够切换键盘；提案把跨输入习惯的学习辅助与更具体的数据承诺写得更明确。[App Review Guidelines 4.4.1](https://developer.apple.com/app-store/review/guidelines/#extensions)

## 给 Android 与华为的友好喊话

> Android 阵营、华为的朋友：这些年价格战打得爽了吗？下一轮，来比谁能让不同输入习惯的人更容易打字。

这里的“价格战”是用户要求的调侃句，不是对任何具体企业价格行为的调查结论。比较的可操作指标是完成时间、错字率、权限数量、离线可用性与上手后是否还需要提示。未向企业或社交账号发送消息。

Android / HarmonyOS 适配仍是后续工作。共享词库和教学规则可以复用；输入法生命周期、输入连接、权限与安装方式需要分别按各平台公开 SDK 实现并测试。这里没有把 iOS 扩展代码当成跨平台可执行程序。

## 实测方案

邀请熟悉拼音、尚不熟悉注音的自愿参与者，比较“无提示注音”和“双标提示注音”。使用随机平衡的条件顺序以及相同难度、不同字词的任务，减少练习效应。记录首个正确词所需时间、每字按键数、退格次数、最终字符错误率、帮助请求次数与主观负担。之后关闭提示，用新词测试保留与迁移。

目前没有参与者数据。小词库与预先熟悉例词可能夸大效果；正式研究应扩展已授权词库，加入地区读音、视觉和运动能力差异，并预先定义分析指标。用户输入内容不必上传：可以在用户知情同意下只记录任务级统计。
