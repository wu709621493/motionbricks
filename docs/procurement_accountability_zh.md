# 采购与仓储效能算法：年度授权、库存与责任记录

创意与需求：吴孟城（Windy Wu）。AI 辅助实现与整理。2026-11-08。

## 目标与交付范围

老板预先批准用途、预算和采购规则，智能体处理规则内的重复采购，员工只处理异常。
每批物资有去向，每个环节有负责人，每次异常有证据，正常流程尽量不占用人的时间。
预算是支出上限，不是必须花完的目标。记录谁经手不等于认定谁有过错。

本 PR 提供独立、标准库实现的 CPU 离线参考原型，不依赖 MotionBricks 的 GPU 推理路径。
它模拟订单预算预占、收货、领用、结算和取消；没有真实商家、钱包、银行卡或支付接口。
`RESERVED` 仅表示本地模拟订单已占用预算，`SETTLED` 仅表示模拟账本结算，均不是外部交易凭证。
本设计也不表示 ChatGPT 已提供企业自主采购功能。

## 年度 10,000 美元 A4 纸示例

一个数据库只管理一个明确规格和包装单位的 SKU、一个币种、一个授权版本、一个预算年度。
金额以整数最小货币单位表示；USD 10,000 = 1,000,000 美分。禁止浮点金额和布尔值代替整数。
授权包括负责人、唯一认可供应商、年度额度、单笔限额、含税运费的单位价格上限和目标库存。
本版不做供应商竞价；多供应商比较是后续扩展。

```text
可用库存 = 实际可用实物库存 − 已预留库存
在途库存 = 未取消订单数量 − 已验收可用数量
补货量 = max(0, 目标库存 − 可用库存 − 在途库存)
订单总价 = 补货量 × 每包报价 + 本单税费及运费
可支配预算 = 年度额度 − 已结算支出 − 未结订单承诺金额
```

损坏或不符合规格的实物不计入可用库存。目标库存可由需求和交期加安全余量确定，
但本版由人预设，不声称已实现需求预测。已预留库存也是固定初始化值。
收货增加库存并减少在途，不能导致重复补货；完整收货后才能按原订单金额模拟结算。
结算把金额从承诺支出转到已结算支出，不重复扣预算。未收货、未结算订单取消后释放承诺金额。
部分收货、退货、退款、发票差价、损耗和盘点更正需要后续人工对账流程，本版不自动处理。

初始化须使用新的独立预算范围，不可把已有年度支出遗漏后重新授予全额预算。
同一个预算范围必须使用同一数据库；复制数据库或为每个智能体另建数据库会破坏共同额度约束。
年度采用 UTC 日历年；过期或尚未开始的年度不能产生新订单。旧订单仍可收货、领用、结算和取消。
跨年迁移、财年和公司时区策略尚未实现，不能通过新建文件掩盖旧承诺支出。

## 职责如何落实到人

| 环节 | 负责人 | 记录／验收依据 |
| --- | --- | --- |
| 制定预算、规则 | 预算负责人 | 授权版本、年度、币种、限额、采购范围 |
| 补货申请与下单 | 采购负责人；智能体执行 | 当前库存与在途、报价凭证、供应商、数量、预算承诺 |
| 收货 | 实际收货人 | 可用实收数量、送货凭证；不把坏货当作合格收货 |
| 领用 | 仓管经办人及实际领用人／部门负责人 | 数量、用途、领用凭证、领用对象 |
| 结算 | 预算负责人 | 完整收货、模拟发票／付款凭证、原订单金额 |
| 盘点与异常处置（设计，尚未实现） | 库存负责人及对应环节负责人 | 账实差异、可控因素、解释和纠正措施 |

事件记录包含顺序号、UTC 时间、请求标识、授权版本、操作人、输入依据和结果。
代码核对操作人标签是否对应授权角色；标签须由可信调用端注入，不能让聊天模型自行填一个姓名就取得权限。
本版没有企业身份认证、组织角色目录或人事考核接口。领用按包／箱记录，不逐张登记。
采购负责人可以管理规则内的智能体执行，不要求每一笔都手工点击审批。

责任评价应基于该人负责环节的及时性、准确性、异常报告和实际可控范围。
不能把领用量大直接认定为浪费，也不能把供应商迟到全部归责仓管；允许解释、复核和更正。
不输出员工惩罚分数，不以姓名排名替代过程调查。记录保留期限与访问范围由企业明确配置。

## 重复与并发控制

每次操作在 SQLite `BEGIN IMMEDIATE` 事务中读取库存／预算、校验、写订单和事件，失败整体回滚。
多个本机进程共享同一文件时，补货计算和预算占用被串行化。
请求标识绑定完整操作、操作者和输入：相同请求重试返回原结果；同标识换内容会拒绝。
重启后仍保持该行为。收货、领用也需沿用同一业务事件标识重试。
不同标识的同一实物收货无法自动辨认，生产系统必须采用唯一送货单行号和领用单号。
`NO_ORDER` 结果也缓存；库存变化后的新需求应使用新标识，不能重用已完成的请求。

仅成功操作和无需补货的结果写入事件表；拒绝请求目前抛出异常，不产生持久拒绝审计。
事件表经接口只追加，但数据库管理员能直接修改它，因此它不是防篡改审计系统。
取消只是本地模拟状态变更；真实系统必须确认供应商取消成功后才释放承诺。

接入真实公司渠道前，还需独立实现身份认证与权限校验、授权撤销、报价有效期与币种验证、
凭证校验、拒绝审计、业务级去重、库存更正、备份恢复和商家状态对账。
本地 SQLite 事务不能保证远程商家恰好下单一次；外部接入应采用事务发件箱、商家幂等键、
状态查询和补偿流程。结果未知时保留承诺、停止盲目重试并交给负责人处理。

## 效能如何验证

本版验证账本约束，没有真实企业试运行数据，不能宣称已经节省某个百分比的费用或人力。
不把不同量纲强行合成一个个人排名。建议在相同需求规模下与人工流程比较以下指标：

| 指标 | 计算与解释 |
| --- | --- |
| 每次补货人工耗时 | 询价、录入、审批、收货、对账和维护规则的人工分钟总和／完成的补货次数 |
| 缺货影响 | 缺货导致的实际工作中断分钟；同时记录业务量，避免需求差异造成误判 |
| 库存与损耗 | 时间加权平均库存、坏货／报废数量及成本；不以少买但频繁缺货为优化成功 |
| 异常处理 | 已到期异常中未解决的比例、同类问题复发次数；责任归属需人复核 |

净节省人工时间 = 基线人工时间 − 新流程人工时间 − 额外维护与纠错时间（这些时间不能重复计入）。
登记动作本身的耗时也要纳入；涉及多人批量领用时可记录部门领用负责人和对应凭证。
下一阶段应增加异常工单、盘点和实际耗时采集，再进行可复核的试运行比较。

## 运行和验证

从仓库根目录运行，Python 3.12+，不需要安装项目依赖：

```bash
python -S -m unittest discover -s tests/procurement -v
python -S -m motionbricks.procurement
```

演示使用临时数据库和虚构人员／凭证：初始 5 包、目标 20 包，每包 600 美分、税运费 300 美分，
补货 15 包，共 9,300 美分。完整收货、结算并领用 2 包后，库存 18 包、剩余额度 990,700 美分。
输出 `simulation_only: true`。金额与包装规格仅用于验证程序，不是市场价格建议。

测试覆盖年度／单笔／含税运费单位限额、授权角色、年限、预留库存、收货数量、部分到货、
取消释放、重复结算、失败回滚、重启后幂等、多进程不同请求争用以及多进程同请求重试。
专用 CI 配置为 Ubuntu x86-64、Ubuntu ARM64、macOS ARM64 × Python 3.12／3.13。
配置矩阵不等于远端已通过；实际状态以本 PR 对应提交的 Actions 结果为准。
