# 丁饶算法 / Ding Rao v0.1

创意与命名：吴孟城（Windy Wu）。形式化、代码与初始语义标注：AI 辅助。
日期：2026-11-03。用户提出的名称原样保留，不推定“丁”“饶”分别指何人。

这版为 MotionBricks 增加一个离线的**叙事语义补偿层**：把文献里“谁做什么、
想做还是已经做、身体如何变化、为何坚持、对谁行动”保存在可追溯的记录中，
用其中有依据的动作标签筛选动作素材候选。另将帝王的行为记载与终年记载按人物
连接，保留缺失、计龄差异和来源冲突，供后续史料研究。

这里“补偿”的对象是只看动作动词时丢失的语义。当前不是人体耗能、疲劳或寿命
补偿公式，也未改变 MotionBricks 的模型权重、姿态或实时运行代码。

## 从这两句到完整人物叙事

柳永《蝶恋花·伫倚危楼风细细》（亦名《凤栖梧》）中的抒情主体与“伊”构成关系。
本版将“伊”保留为未具名对象；不把抒情主体直接认定为作者本人，不虚构其伴侣
身份、性别、具体经历或死亡原因。词句不是临床观察。

| 片段 | 本版标注 | 可保留的信息 | 不能自动转换成 |
|---|---|---|---|
| 衣带渐宽 | 身体状态意象 | 逐渐消瘦的描写 | 解腰带动作、体重减少多少公斤 |
| 终不悔 | 意愿/立场 | 对关系的坚持 | 无穷重复动作、必须继续或不能撤回 |
| 为伊 | 人物关系 | 动机指向未具名对象 | 一段已证实的人物传记 |
| 人憔悴 | 身体状态意象 | 精神或形貌的耗损描写 | 疾病诊断、剩余寿命、力量下降系数 |

仅给这两句时，动作候选返回 `ABSTAIN`，同时输出完整语义上下文。信息不足时
保留故事，比从“衣带”硬造一个动作更符合这个算法的目标。

全词提供更多背景：伫倚与远望 → 无言、春愁 → 拟以酒歌排遣 → 强乐仍无味 →
身体意象变化而不悔。该顺序是文学叙事顺序，既不是实测时间序列，也不证明心理
因素导致消瘦。现有标注为一种可审查解读，尚未进行独立的文学专家复核。

| 全词片段 | 状态 | 用于动作筛选 |
|---|---|---|
| 伫倚 | `depicted`、直接动作 | `stand_lean` |
| 望极 | `depicted`、直接动作 | `look_far` |
| 拟把疏狂图一醉 | `intended` | 不当成已经饮酒 |
| 对酒当歌 | `uncertain` | “拟”的作用范围存在解读空间，暂不当成已做的歌唱 |
| 强乐还无味 | 情绪/排遣效果 | 保留上下文，不作为关节目标 |

## 已实现的算法

代码：[motionbricks/ding_rao.py](../motionbricks/ding_rao.py)。只用 Python 标准库，
复用已有的 [zero_guard.divide](../motionbricks/zero_guard.py)。不需要 GPU、Torch、
TensorRT 或模型下载。

1. **证据校验**：输入带出处的文本片段和显式标注。检验来源、人物、全局唯一事件
   ID、原文跨度、引用原句、类别和模态。所有跨度为未归一化字符串的 Python Unicode
   code point 半开区间 `[start, end)`。空字段、错位引文、悬空引用拒绝处理。
2. **叙事补偿**：依原文位置输出事件。动作、身体状态、意愿、关系、情绪分别保留；
   每个未进入动作集的事件都有原因。来源与解释不因筛选被删掉。
3. **动作筛选**：只纳入主体相符、直接实施、`depicted` 或 `reported` 的动作。
   “命他人做”、否定、拟做、不确定的动作不进入主体动作集。`depicted` 是文学
   描写，`reported` 是史书记载，两者均不是动作捕捉数据。
4. **候选排序**：给定用户自行标注的素材目录，只接受 rig 匹配、标签非空且全部
   获得当前片段支持的候选。使用下式计算标签集合的 Jaccard 分数，并按 ID 稳定
   处理并列。分数不是正确率、历史可信度或运动质量。
5. **人物对照**：以人物 ID 连接正史行为和年龄证据；同一人多条行为记录不会变成
   多名独立样本。寿命从不进入动作排序。

设当前片段可支持的动作集合为 \(A\)，候选标签为 \(T_j\)：

\[
S_j = \frac{|A\cap T_j|}{|A\cup T_j|},\quad
T_j\ne\varnothing,\ T_j\subseteq A,\ \mathrm{rig}_j=\mathrm{rig}_{request}.
\]

不满足条件的候选被拒绝。`A` 为空或没有合适候选时返回 `ABSTAIN`，不注入 epsilon、
不制造一个零分姿态。保留每个结果的 `evidence_ids` 和未覆盖标签。
保守的子集条件也会拒绝含额外动作的真实素材；现阶段宁可要求重新切片或标注。

**本版需要预先标注，未实现任意古文自动理解。** `narrative_brief` 按片段 ID 使用
已存标注，遇到新诗文必须先建新片段。结构校验不能证明引文真实、数字转写正确、
主语判断正确或素材标签真实。当前数据由 AI 辅助标注并核对网页，独立人工复核待做。
不处理跨片段指代消解、同名人物自动合并、同一动作先否定后实施等复杂时态；这些
须拆成带有明确解释的片段再审阅，不能把文本顺序当执行顺序。

## 正史种子与寿命字段

数据：[seed.json](../data/ding_rao/seed.json)。12 个片段、25 项语义标注、5 个来源；
含一首词的全文与重复摘句演示，以及四位帝王的本纪片段。年龄引文单独保存。

| 人物 | 本版行为例子 | 本版终年证据 | 处理 |
|---|---|---|---|
| 汉武帝 | 《汉书》“上耕于鉅定” | 选用死亡条文没有直接给出终年 | 缺失，不用在位年数代替，不补写常见二手年龄 |
| 唐太宗 | 《旧唐书》校猎、“自射鹿” | “年五十二” | 保存记载值 52，计龄未校定 |
| 宋太祖 | 《宋史》“步至晋王邸”、郊猎 | “年五十” | 保存记载值 50，计龄未校定 |
| 明宣宗 | 《明史》下马、问农事、“取耒三推”、狩猎 | “年三十有八” | 保存记载值 38，计龄未校定 |

表内简体转述供阅读；JSON 保留所核网页的繁体引文。记录历史中的狩猎、射箭等
行为不表示建议重演。宋太祖“命作机轮”保留为委托事件，不计为其本人造机器；
明宣宗自述“三推已不胜劳”保留为记载中的身体状态陈述，不等于测量到的疲劳。

`age_claims=[]` 表示当前证据缺失，不表示年龄 0。`years` 是人工转写的原文数字。
`basis` 分别支持 `source_reported_unspecified`、`nominal`、`completed_years`；
本次三个非空年龄全部为第一种。不自动将虚岁减一当成周岁。
同一口径的不同记载保留各自引文、来源与最小/最大记载值，并标记 `conflict`；
不取平均、不给可信度打分，不跨口径合并。日期只保存史书纪年标签，未擅自换算
公历。死亡原因本版均为 `not_coded`。

`history_report` 输出 4 位帝王、3 位有终年记载的种子样本，并按行为列出唯一人物
及其中有年龄记录的人数。例如狩猎标签对应唐太宗、宋太祖、明宣宗，共 3 人；
这是选定片段的收录情况，不是“所有狩猎帝王的寿命分布”。
重复引用不增加样本量；未标到的行为不能作为“从未做过”的零值对照组。

### 全史扩展范围

目标为逐卷扩展，当前只查阅《汉书》《旧唐书》《宋史》《明史》中的上述部分。
以下二十部尚未录入：《史记》《后汉书》《三国志》《晋书》《宋书》《南齐书》
《梁书》《陈书》《魏书》《北齐书》《周书》《隋书》《南史》《北史》《新唐书》
《旧五代史》《新五代史》《辽史》《金史》《元史》。不能将四部局部样例称为
完成“历代正史帝王”数据集。《清史稿》若加入，应另标未定稿身份，与二十四史
区分。当前未录入，不借清代帝王的长寿印象填补样本。

规模化录入时须先规定帝王纳入名单（含幼主、短命、废黜、遇害及失踪者）、
身份别名和史书版本，完整记录抽样卷次与未录入项。行为记录须分本人实施、下令、
仪式、作者评语、转述与传闻；补充发生时间、是否确有频率或持续时间，以及每部
史书的覆盖范围。寿命须保存生卒证据、历法、名义计龄、争议和无法定年的区间。
至少两位独立标注者核对身份、动作及年龄，再分析一致性与漏标。

寿命与行为研究还需处理王朝/时代、战争和遇害、医疗条件、政治地位、亲缘、
幼年死亡、登基时年龄与入组时间。活得久的人有更多时间累积行为记载，不能用
“一生提到狩猎多少次”直接回归寿命。即使未来做时间变化的生存分析，也不能消除
史书选择、胜者叙事和未测混杂。当前既未估计相关性，也未估计因果效应。

## MotionBricks 接口边界

已有 [SmartPrimitiveData](../motionbricks/runtime/smart_primitive.py) 需要真实的 rig、
`target_poses`、节点变换、接触空间与序列；[MotionPlayer](../motionbricks/runtime/motion_player.py)
接收姿态数组。本版侧车输出只到**编排素材的候选与解释**，不可直接传入这些接口。

`rank_candidates(corpus, passage_id, catalog, rig=...)` 是已实现的接入点。目录中的
`id` 应由调用方对应到其审核过的素材；算法不读素材文件、不验证其标签、不调用
引擎。附带目录只有合成元数据，没有假冒实际 BVH/CSV 文件的路径。

后续接入顺序：人工标注并审核实际素材 → 查询候选和语义侧车 → 作者选择、补全
时长与目标姿态 → 通过现有素材编辑/验证流程 → 在仿真中比较输出。相同“远望”
可以伴随多种情绪，是否要低头、放慢或改变姿态须有作者或测量依据；本版不从
“憔悴”推导任意速度、力矩或形体改变。帝王终年只留在史料报告，永不作为动作参数。
“终不悔”也不覆盖 [crew countdown](crew_countdown.md) 的 HOLD/ABORT 或动态同意。

## 复现与结果

从仓库根目录运行，无需安装项目依赖：

```sh
python -S -m unittest discover -s tests/ding_rao -v
python -S -m unittest discover -s tests/zero_guard -v
python -S -m motionbricks.ding_rao data/ding_rao/seed.json
python -S -m motionbricks.ding_rao data/ding_rao/seed.json --passage poem_couplet
python -S -m motionbricks.ding_rao data/ding_rao/seed.json \
  --passage poem_full --catalog data/ding_rao/demo_catalog.json --rig soma
python -S tools/ding_rao/demo.py > /tmp/ding_rao_demo.json
```

固定演示：[demo_output.json](ding_rao/demo_output.json)。合成目录全词排序为
`demo_lean_and_look`（1.0）、`demo_lean_only`（0.5）、`demo_look_only`（0.5）；
解腰带、拟饮酒、附带饮酒的倚靠以及错误 rig 的候选被拒绝。摘句返回 `ABSTAIN`。
分数只核验集合运算，无动作质量/心理理解/历史真实性的实验结论。

测试包括摘句与全词区别、未遂/否定/委托/他人动作、额外标签混入、rig、空输入、
独立可算的分数和并列排序、缺失及冲突年龄、同人重复计数、年龄不影响排序、
引文移位、异常数字、来源错配、不可变输出与无第三方依赖 CLI。
新增测试接入现有 Ubuntu x86-64/ARM64、macOS ARM64 × Python 3.12/3.13 CPU CI。
本地结果与远端 CI 状态应分别报告。

### 后续实测

先冻结一份未参与规则设计的古文片段集，分动作/状态/意愿/关系评估主语、模态、
出处与拒答正确性，比较只取动词的基线和本方法；本次种子不能用作泛化准确率。
再以真实标注素材进行盲评：是否选对主体动作、是否保留人物动机、是否避免错误
身体解释，以及需要多少人工修正。没有实测之前，不宣称胜过现有动作检索系统。

与仓库现有感知理论记录对接：L1/L2 用标注和释义核验，L3 用未见片段迁移验证；
L4 要求至少三位独立人类读者准确解释输出与拒答；L5/L6 仍需人机感知及力/温度
实验，文本测试不能代替；L7 延续既有“定义待明确”状态，不补造标准或通过记录。
