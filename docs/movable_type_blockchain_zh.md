作者提案：吴孟城（Windy Wu）  
实现与技术整理：Codex  
版本：0.1；整理日期：2026-11-14（Asia/Shanghai）  
实现基线：`f43c457d27126fbb3d6f3d62e896ad3c0f1d7161`

> 老婆，重构一遍区块链技术，用“活字印刷”技能和我们代码仓的工具😘

本次交付是一个可运行的区块链核心实验：固定规则、确定性执行、内容承诺、
历史连接、包含证明、独立对象重放和带外锚点恢复。应用选择仓库实验凭证，
将已有整数工具的回执作为第一份真实输入。当前由一个可信写入者确定顺序；
没有签名、节点通信、PoW、PoS、BFT、代币或智能合约虚拟机。

## 1. 找回原意，再把比喻变成接口

此前讨论将“活字印刷”理解为可复用字符模块和模块化组件库，并用排版、印刷工、
校对和书页比喻组链、节点、共识与账本。本次检索找到了这一讨论口径，
但没有找到可读取的独立同名 `SKILL.md`；因此这里应用已有方法，
没有声称调用或安装了一个找不到的技能包。

以下对应关系是本次工程细化。它修正了“每一个活字就是一个区块”的粗略对应：
可复用的是规则；每次发生的事件及其顺序必须分别留印。

| 印刷概念 | 本次接口 | 约束 |
| --- | --- | --- |
| 活字 | `TYPE_RECORD` / `TYPE_REVISE` | 固定版本、内容寻址的规则描述；不接受远程代码 |
| 字库 | `TYPES` 与 `RULEBOOK` | 固定规则集合及准入上限；修改语义必须升级版本 |
| 排字 | `entry(type_id, key, artifact_sha256, …)` | 模板引用与本次参数；精确字段和类型检查 |
| 版面 | `Ledger.propose(entries)` | 有序事件列表、前块承诺、Merkle 根、执行后状态根 |
| 校对 | `Ledger.append(block)` | 在本地重算全部转移；任何一步失败则不修改内存 |
| 印本 | 规范化区块字节与快照 | 对外返回副本；更正通过追加修订事件表达 |
| 决定采用哪一版 | 后续共识与授权层 | 本版只有可信单写入者；校验通过不等于网络达成共识 |

**活字可以复用，发生过的落印必须保留。**
把新摘要追加到账本不会删除旧摘要，也不会证明旧摘要或新摘要的科学结论正确。

## 2. 重构后的职责

1. **表示层**：复用 `radix_ipc.canonical/unpack/fields/integer`，采用排序键、ASCII 转义、
   紧凑 JSON，拒绝重复键、非规范字节、超深嵌套与非有限数。应用参数只接收受限 ASCII
   键、SHA-256 与真正的整数；布尔值、浮点数和未知字段不能混入整数协议。
   这是仓内 v1 编码约定，不宣称符合其他语言的通用 JSON 规范化标准。
2. **规则层**：`type_id` 承诺固定描述，包括名称、版本、字段与效果标识。
   描述不是代码的形式化证明，升级执行语义必须同时更改版本及规则集，不能静默换实现。
3. **执行层**：依顺序处理创建和比较版本修订，生成新的证据状态。
   状态中只保留当前摘要与修订号，完整事件仍在区块历史中。
4. **承诺层**：区块头绑定链身份、规则集、区块高度、前块、事件数量、事件根和状态根。
   自定义 SHA-256 承诺使用不同域标签隔离模板、规则集、创世、区块头与状态。
5. **顺序层**：本版只接受当前已钉住头部的直接后继。旧块、同高冲突和跳高都失败，
   不执行“挑最长列表”等未经论证的分叉选择规则。
6. **存储层**：同目录临时文件、文件 `fsync`、原子替换，以及 POSIX 目录 `fsync`。
   恢复时按外部链 ID 与可信头部重放；单个文件自己的摘要不能成为自己的信任来源。

参考原理：[Bitcoin 原始论文](https://bitcoin.org/bitcoin.pdf)将数字签名、
双花处理、时间顺序及工作量证明结合起来；本文没有实现其网络或共识算法。
事件树使用 [RFC 9162 §2.1](https://www.rfc-editor.org/rfc/rfc9162.html#section-2.1)
的二叉树形状和叶/内节点域分离，支持非二次幂长度。这里只复用树算法，
没有实现 Certificate Transparency 协议。

## 3. 两枚最小活字

| 模板 | 参数 | 状态转移 | 重放与竞争处理 |
| --- | --- | --- | --- |
| `evidence.record@1` | `key, artifact_sha256` | 不存在的键创建为 revision=1 | 同一键再次创建失败 |
| `evidence.revise@1` | 上述参数及 `expected_revision` | 仅当前版本相符时换摘要并将版本加一 | 旧版本重放、缺失键和竞争修订失败 |

创建的键不能删除或再次创建。修订可以保留相同摘要，但仍会消耗一个修订号；
版本号是发生次数，不表示新结果一定优于旧结果。没有作者身份、权限或签名检查；
任何能够提交给可信写入者的调用方都可能提出修订，部署前必须补齐授权。
防重放范围限定为本链的键和预期修订号，不是全球请求的 exactly-once 保证。

例如，同一实验由 `revision=1` 更正到 `revision=2`，旧证据仍在第一块。
再次提交要求 `expected_revision=1` 的事件会失败。若希望把另一轮实验作为独立证据，
必须使用不同实验键，不得把模板复用误当成事件去重。

## 4. 仓内工具如何实际结合

| 已有工具 | 本次用途 | 不据此声称 |
| --- | --- | --- |
| `motionbricks/radix_portability.py` | 二进制、平衡三进制、平衡七进制分别计算同一整数点积并对照 Python 参考值 | 改变进制提高密码强度或共识安全 |
| `motionbricks/radix_ipc.py` / `radix_worker.py` | 可选运行有总期限的二/三进制子进程；父进程校验并记录回执 | 两个子进程就是独立分布式节点或 BFT |
| 既有规范化与边界校验函数 | 统一序列化、类型拒绝与读入上限 | 编码规范等同于身份认证 |
| 标准库 `hashlib` 与文件 API | 内容摘要、状态承诺与快照 | 哈希证明结果真实、数据永久可取或磁盘断电可靠 |
| 仓库现有 unittest / CI 模式 | 故障注入、重放、跨平台矩阵 | 尚未完成的远端 CI 已通过 |

示例向量为 `[7,-11,5,2] · [-3,9,0,-1] = -122`。
示例先生成真实整数后端回执，再将其规范字节的 SHA-256 记入 `radix:dot`。
它同时演示另一个夹具的追加更正、包含证明、两个独立 Ledger 对象重放及快照恢复。
两个对象处于同一个进程，测试的是确定性验证，不是抗恶意节点能力。

PyIgnite 的浮点 PE/FCBlock 与本次哈希或规则执行没有适当的直接结合点，
本版不将神经网络误差带入账本规则，也不更改已有 PyIgnite 实现或验证结论。

## 5. 运行与复现

在完整仓库根目录，Python 3.12 或 3.13，无需安装主项目的 GPU 依赖：

```sh
python -S -W error::ResourceWarning -m unittest discover -s tests/movable_type_ledger -v
python -S -W error::ResourceWarning -m unittest discover -s tests/radix_portability -v
python -S -W error::ResourceWarning -m unittest discover -s tests/radix_ipc -v
python -S -W error::ResourceWarning tools/movable_type_ledger_demo.py --ipc --out-dir /tmp/movable-type-demo
```

输出目录必须为空；换一个新目录即可保存下一轮实验。`--ipc` 使用既有 Linux/macOS
监督器，可省略该参数仅运行进程内整数后端。此版 CI 覆盖 Ubuntu x86-64/ARM64、
macOS ARM64 与 Python 3.12/3.13 六个组合；实际本地结果及远端状态分开记载。

输出：

- `radix-receipt.json`：实际运行的原始回执，包含时间度量；其摘要写入账本。
- `ledger.json`：两块完整规范化历史。包含原始记录与随后更正事件。
- `report.json`：恢复结果、包含证明及外部锚点的演示值。

示例为了方便将 report 放在同一目录。真正的可信锚点须经独立可信渠道保留，
攻击者若能一起替换 ledger 和 report，则这个演示没有提供身份认证。
回执中的计时随运行改变，因此不同次运行的摘要和链头可以不同；
确定性要求是**同一份输入字节重放得到同一份状态与链头**。

本地验证记录和原始演示文件见 [结果目录](results/movable_type_ledger_20261114/validation.json)。
模块入口：[movable_type_ledger.py](../motionbricks/movable_type_ledger.py)；
演示入口：[movable_type_ledger_demo.py](../tools/movable_type_ledger_demo.py)。

## 6. 验证重点与可声称的边界

新增测试包含：模板复用、顺序承诺、调用方修改隔离、完整失败回滚、旧块重放、
同高分叉、过期修订、未知版本、类型与字段拒绝、容量上限、每个树长 1–64 的所有
叶子包含证明、独立迭代 Merkle 参考、奇数叶形状、证明篡改，以及快照读写故障。

文件写入测试注入文件 `fsync`、`replace` 和目录 `fsync` 异常。
原子替换前异常应保留上一个文件并清理临时文件；目录 `fsync` 位于替换之后，
此时新文件可能已经可见，程序仍报告失败，持久性不能据此确认。
这不是物理断电、设备损坏或文件系统崩溃测试；崩溃可能留下临时文件，恢复只读正式文件。

| 性质 | 本版结论 |
| --- | --- |
| 模板与事件分离、确定性执行、摘要校验 | 已实现并有针对性测试 |
| 篡改或删尾后按原可信头部恢复 | 应拒绝；有测试 |
| 攻击者重写全部历史并提供新的“可信”头部 | 仍可构造内部一致的账本；测试明确演示这一信任边界 |
| 包含证明 | 证明事件在给定根和树长中；根、树长必须来自可信区块头 |
| 数据可用性、来源授权与证据真实性 | 未提供；知道摘要不能还原缺失凭证 |
| 多写入者并发、网络分区、拜占庭共识、最终性 | 未实现；API 按串行可信单写入者使用 |
| 空间缩减、吞吐提升、能耗优势 | 未测量；小模板的摘要引用可能比短操作码更大 |
| 生产区块链替代或安全审计 | 尚不能声称 |

v1 上限：每块 1–64 项、最多 256 块、4096 个键、每块规范字节不超过 32 KiB、
完整快照不超过 2 MiB。为了保持教学实现可核查，追加时还会检查完整快照大小，
恢复也逐块重放；这一小规模实现含重复序列化成本，不是高吞吐实现。

## 7. 下一阶段如何接入真正的网络

保持确定性核心不变，由独立的授权与顺序协议先确定可接纳的区块和可信头部，
再交给本地核心逐项核验。下一阶段必须具体选择成员身份、签名方案、故障模型、
投票或工作量规则、最终性、密钥轮换与升级程序，才能实现相应适配器。
本版尚无可插拔共识适配器的代码，也没有用“多数 Python 对象相同”代替该工程。

适合先做的延伸是：将其他仓库实验回执作为新的外部凭证输入；
每种回执另行验证单位、环境、提交和证据状态，避免把“有哈希”误写成“实验通过”。
只有完成独立锚点、签名授权与网络故障测试后，才讨论真实多节点部署。
