# 医院、JJPCS 月子中心与养老设施工作收尾总结

截至 2026-11-07。构想与项目决策来自吴孟城（Windy Wu），AI 协助整理与核对。

本阶段以医院、产后母婴照护中心与养老设施的建筑和照护需求为收尾范围，将讨论、法规线索和空间原型归档。用户于本日要求结束持续追踪，JJPCS 法规与安全变化监测已停止。后续如启动具体建设或服务项目，由新的明确任务确定复核范围。

JJPCS 当前处于拟议框架阶段，地点、床位数、许可类别、医疗服务范围及联邦项目参与关系均待确定。本总结的成熟度为概念设计与资料归档。实际设计和运行标准需要在上述条件确定后，由相应专业人员与主管机构核定。

## 已形成的设计要求

以下为用户提出的框架原则及本阶段整理的设计建议。各项法定义务须逐条确认依据和适用条件。

| 主题 | 保留的要求 | 具体落地时需要核定的内容 |
| --- | --- | --- |
| 尊严与自主 | 尊重母婴、患者及长者的隐私、休息、求助和个人选择，支持母乳喂养且尊重拒绝或其他喂养选择 | 可理解的服务说明、同意及撤回流程、投诉渠道、安静空间与隐私边界 |
| 建筑协调 | 医院与月子中心图纸在功能、坐标、标高、转运路径和交接点上协调；概念原型采用连接两翼的临床连廊 | 地块关系、产权与许可边界、防火分区、门禁、担架及轮椅通行、室外救护车接驳 |
| 客用与医疗废物运输 | 保留用户提出的客用电梯与医疗废物电梯分开的项目设计要求，设置后勤收集出口 | 污物产生点、封闭容器、暂存、运输、清洁及交接全程，按所在地规则核查电梯和通道方案 |
| 夜班人员配置及资质 | 按服务范围、照护强度与应急职责配置人员，安排休息替岗与缺勤补位，纳入疲劳管理 | 护理与非医疗岗位边界、执业资质、各时段最低配置、交接班、突发事件增援及持续服务能力 |
| 紧急转诊 | 明确识别异常、启动求助、联系接收方、运送和交接记录的责任 | 按母亲、新生儿及长者分别制定升级路径，核定接收能力、夜间联系人、运输条件与备用接收机构 |
| 室内空气与山火烟霾 | 将日常通风、烟霾期间过滤、室内监测及停电工况纳入同一设施方案 | 由暖通与感染控制专业人员确定设备、监测点、动作阈值和恢复条件，评估关闭外气时的通风影响 |
| 备用电力 | 识别求助通信、应急照明和拟使用设备的关键负载 | 按许可及设备确定容量、运行时长、切换、维护、燃料或电池布置及故障处置 |
| 感染控制 | 建立症状识别、手卫生、清洁消毒、物资供应和患病员工返岗流程 | 按服务类别确定隔离或转诊能力、呼吸防护与人员培训，明确相关强制规定及官方建议的区别 |
| 多语言知情同意 | 记录首选语言，提供适合服务情境的合格口译和可理解材料，并核验理解 | 口译资质、夜间可用性、远程服务、隐私、译文审校、同意及紧急例外的当地依据 |

客用与废物电梯分隔是本项目明确的设计选择，其法规依据需按实际机构和地点复核。原型中的空间连通需要与接收协议、值班能力及交接责任共同评估。

## 三类机构的适用性分别确认

| 场景 | 首先确定的服务及分类 | 需要单独核实的事项 |
| --- | --- | --- |
| 医院 | 急诊、住院、门诊、围产或新生儿服务范围，州许可与 Medicare 参与关系 | 医疗岗位资质、人力规则、医院建筑要求、转诊和接收义务、认证及检查范围 |
| JJPCS 产后母婴照护中心 | 住宿、生活照护、健康教育与医疗护理分别由谁提供，服务是否触发某一许可类别 | 医疗与非医疗职责、母婴留住及转诊条件、多语言同意、夜间求助和转运安排 |
| 养老设施 | 根据实际服务确认住宿支持、辅助生活、记忆照护、专业护理等类别 | 州许可、联邦项目条件、居民照护强度、夜班能力、行动及认知支持、疏散和医院交接 |

加州、俄勒冈州、华盛顿州的许可分类与监管要求须分别核查。联邦要求还需逐项核对参与计划、资助、提供者身份或其他适用条件。“养老院”目前仅作为项目场景总称，本阶段尚无独立养老设施模型或完整规范审查。

## 已有空间原型与验证范围

2026-11-07 核对仓库时，Minecraft 医院原型 PR #33 为开放草稿，源文件位于该 PR 的提交 `f1f85e97c25704fb631c19fdf5c7142247c6c3ce`。主分支此次检查未包含该示例。[PR #33](https://github.com/wu709621493/motionbricks/pull/33)

该示例通过独立 Python 脚本生成 Minecraft Java 1.21 数据包，包含医院与月子中心两翼、两层临床连接通道、客用和废物竖向通道、隔墙中的交接容器及后侧收集出口。颜色用于标识临床、客用和后勤路线，脚手架表达竖向移动。执行构建函数会覆盖指定的 41 × 20 × 11 方块区域，使用范围为可丢弃的创作世界。[原型源码固定版本](https://github.com/wu709621493/motionbricks/blob/f1f85e97c25704fb631c19fdf5c7142247c6c3ce/examples/minecraft/jjpcs_hospital.py)

验证范围为脚本定义的室内网格可达性、临床区域与废物区域集合分离，以及 ZIP 结构完整性。游戏内加载、实际移动、担架通过、电梯运作、通风、烟气传播及消防疏散仍待独立验证。连通性断言仅反映模型的通行规则。生成器使用标准库独立运行，与 MotionBricks 动作推理的接入仍待实现。

此前检索覆盖了三州及联邦的指定主题，但各源访问完整度存在差异。部分华盛顿州页面直接访问受限，曾通过官方索引补查。本阶段未取得完整、具版本号的 JJPCS 条文，因此建议按主题编排。完整州别法规清单、养老设施专项审查和具体场址合规结论均待项目条件确定后建立。

## 收尾与后续调用

本阶段保存了三类设施的共同设计原则、各自的许可分类入口、已有 Minecraft 原型状态及三条主要政策线索。持续监测于 2026-11-07 按用户要求停止，本文作为带日期的归档记录。

以后由用户明确启动具体项目时，可按以下次序调用这些材料。

1. 确定州、地块、服务清单、接收人群、床位及许可类别。
2. 邀请建筑、消防、暖通、电气、感染控制和临床团队共同审查图纸与服务边界。
3. 按上述条件复核当时有效的法规、指南、延期及法律效力变化，指定每项要求的负责人。
4. 完成转诊协议、夜班排班与应急预案，并以实际设备和人员进行演练。
5. 根据验证结果决定是否扩展空间原型及接入 MotionBricks。

档案中的已完成工作与待验证事项以上述范围为准。任何后续施工、许可、临床运行及养老照护方案，应形成对应的专业审查记录。
