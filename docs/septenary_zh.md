# 平衡七进制：可核验的整数乘加算法

提议：吴孟城（Windy Wu）；实现、测试与文档：AI 辅助。

在已有二进制／平衡三进制实验上增加 `BalancedSeptenaryBackend`。同一整数点积
通过七进制数位卷积与进位计算，再与原始输入的 Python 整数 oracle 独立比较。
它是二进制 CPU 上的软件算法实验，不是七进制硬件、模型推理或速度／能耗优势的证明。

## 为什么使用平衡七进制

普通七进制每位为 0–6；本实现选择每位为 **−3、−2、−1、0、1、2、3** 的平衡七进制，
便于沿用平衡三进制接口并直接表示正负整数。二者的位权均为 7 的幂，但数位编码不同，
不能互换数组或把普通七进制文本直接作为本接口的数位输入。

低位在前，`x = sum(d[i] * 7**i)`。例如：

| 十进制值 | 三位平衡七进制 tuple | 检查 |
| --- | --- | --- |
| 4 | `(-3, 1, 0)` | −3 + 7 = 4 |
| −4 | `(3, -1, 0)` | 3 − 7 = −4 |
| 13 | `(-1, 2, 0)` | −1 + 14 = 13 |
| 49 | `(0, 0, 1)` | 7² = 49 |
| −122 | `(-3, -3, -2)` | −3 − 21 − 98 = −122 |

`WordFormat(SEPTENARY, w)` 可表示 `[-(7**w-1)/2, +(7**w-1)/2]`。
编码重复执行 `q, rem = divmod(x + 3, 7)`，输出 `rem - 3` 并以 `q` 继续。
负数也使用同一规则；零保留为全零数位。越界直接拒绝，不截断或饱和。

## 乘法、累加与进位

点积 `sum(a[k] * b[k])` 的第 `i+j` 列累加 `a[k][i] * b[k][j]`。
随后从低位到高位，对每列系数 `c` 与前一列进位 `carry` 执行：

```python
carry, remainder = divmod(c + carry + 3, 7)
digit = remainder - 3
```

这满足 `c + old_carry = 7 * new_carry + digit`，数位始终在 −3 到 3 之间。
每列和各列进位保持数值，因此最终数位表示精确点积。后端执行阶段不把整项操作数
解码为 Python 整数来相乘；它使用 Python 小整数运算模拟数位乘法和列累加。
三进制与七进制共享这一卷积实现，分别使用半径 1、3 和基数 3、7。

`n` 项、每项 `w` 位的结果宽度取 `W = 2*w + ceil(log_7(n))`，用整数循环求上取整。
令 `k = ceil(log_7(n))`，输入最大绝对值为 `(7**w-1)/2`，则点积绝对值最多为
`n*((7**w-1)/2)**2 < 7**(2*w+k)/4 <= (7**W-1)/2`，因此完整结果可容纳。
算法仍检查最终进位非零的异常情况。列运算复杂度为 `O(n*w² + W)`，
列系数与结果额外空间为 `O(W)`；接口另保留 `O(n*w)` 的编码输入。

## 接口与兼容性

| 属性 | 七进制后端 |
| --- | --- |
| 类 | `BalancedSeptenaryBackend(width=12)` |
| 编码标识 | `balanced_septenary` |
| 后端标识 | `python-septenary-convolution-v1` |
| 执行分类 | `HOST_SEPTENARY_SIMULATION` |
| 默认输入范围 | −6,920,643,600 到 +6,920,643,600，覆盖有符号 32 位整数 |
| 输入宽度／向量长度 | 1–32 位／1–1024 项 |
| 最大结果宽度 | 68 位（32 位输入、1024 项） |

沿用 schema 1 的字段结构，新增显式编码与执行类别。旧二／三进制请求、默认 CLI 和
`--backend both` 行为保持不变。旧版本消费者不认识七进制标识时应拒绝，不能按三进制解释；
schema 号相同不代表旧后端支持新编码。调用方按后端能力选格式，后端严格检查请求格式。
已有请求摘要、返回版本／格式检查和独立 oracle 检查继续生效。
不同后端对同一输入共享工作负载摘要，编码请求摘要不同。

基于主分支中已合并的 PR #28；七进制使用进程内接口。
[PR #29](https://github.com/wu709621493/motionbricks/pull/29) 的跨进程实验是单独工作，
本改动没有把七进制接入其 worker 或线协议。后续接入必须显式扩展能力、编码白名单和测试。

## 运行与结果

从仓库根目录，用 Python 3.12 或 3.13，无需安装项目依赖：

```sh
python -S -m motionbricks.radix_portability --backend septenary
python -S -m motionbricks.radix_portability --backend all
python -S -m unittest discover -s tests/radix_portability -v
```

默认 fixture 为 `[13,-7,0,42] · [3,11,-9,-2]`，每个后端应返回 `-122`。
`all` 要求输入在三者共同范围内；任何后端失败，CLI 返回 `FAILED` 并退出 1，
不发布部分结果，也不以 oracle 替换失败计算。只在命令行选七进制时，可使用其完整默认范围。

```python
from motionbricks.radix_portability import BalancedSeptenaryBackend, run_dot

backend = BalancedSeptenaryBackend()
assert run_dot([13], [-7], backend)['value'] == -91       # 单项乘法
assert run_dot([13, -7], [1, 1], backend)['value'] == 6   # 求和
assert run_dot([13, -7], [1, -1], backend)['value'] == 20 # 相减
```

13 项新增测试涵盖 1–4 位全部编码、两位数全部 2401 对乘法、60 组固定种子跨后端向量、
32 位七进制输入、进位长度跨越 7 的幂、1024 项极值及完全抵消。另测试禁止后端调用
整值编解码、坏输入／坏返回／陈旧摘要、错误数值和异常拒绝，以及 CLI 兼容与失败语义。
测试同原有 14 项一并纳入 CPU preflight 的 Python 3.12／3.13、Ubuntu x86-64／ARM64、
macOS ARM64 矩阵。实际通过情况以 PR 检查记录为准。

报告分阶段记录转换和运算时间。12 位七进制的逻辑数位较少，不等于 Python 内存占用较少；
计时包括 Python 循环、校验和摘要开销，不能由数位数量推断加速或节能。
本实现没有除法、浮点、模 7 有限域运算、原生七态器件或七维量子系统。
与原接口相同，后端为可信进程内代码，不能抢占卡死调用或隔离进程崩溃。
